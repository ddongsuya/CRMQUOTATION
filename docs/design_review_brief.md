# 디자인 검토 브리프 — CRMQUOTATION

> Claude Design 리디자인 검토용 브리프. 2026-08 기준 실제 코드베이스와 일치.
> **이 문서가 리디자인의 범위 규칙이다. 전 화면 구조 제안 가능 — 단 "구조 자유" 화면은 §7-A의 기능 계약을 반드시 지킬 것. 유일한 규격 고정은 A4 인쇄물.**

---

## 1. 제품 한 줄

CRO(비임상시험 수탁기관)의 **내부 영업 도구**. 독성·효력시험 견적을 규칙엔진으로 자동 산출하고, 고객사→의뢰자→안건(딜) CRM, 시험 일정 간트, 관리자 실적 대시보드까지 하나의 Next.js 웹앱.

**사용자 2명 페르소나**
- **영업 담당자** — 데스크톱 위주. 견적 작성·고객 관리·일일 업무 기록이 메인 루프.
- **관리자(본부장/센터장)** — 전사 실적 대시보드·견적 현황 조회. 이동 중 모바일 조회 빈도 높음.

로그인은 현재 꺼져 있음(개발 단계) → **온보딩·회원가입 화면은 설계 범위 아님.**

## 3. 레이아웃 셸

- **데스크톱**: 좌측 사이드바 264px(8개 메뉴 + "새 견적 작성" CTA 버튼) + 탑바(브레드크럼·테마 토글) + 본문 max 1180 중앙.
- **모바일**: 사이드바 → 햄버거 드로어, 하단 탭바 4개(홈·견적·고객·일정).
- **전역 드로어 시스템**: 어느 화면에서든 회사명/견적번호/업무기록 클릭 → 우측 드로어 패널(스택형, 뒤로가기 지원). 화면 이동 없이 컨텍스트 유지가 이 앱 내비게이션의 핵심 패턴.
- **⌘K 명령 팔레트**: 회사·견적·업무기록 전역 검색(키보드 내비 지원).
- `/quote/print`·`/admin`은 자체 셸(사이드바 없음).

## 5. 플로우 맵 (연결 구조)

### A. 견적 생성 → 수주 (메인 루프)
```
사이드바 CTA "새 견적 작성"
  → /quote/start (효력|독성 선택)
  → 위저드 (고객사 입력 = CRM 자동완성, 신규면 고객관리에 자동 등록)
  → 저장 (견적번호 CK-YYYYMMDD-NNN 발번)
  → /quote/print (A4 견적서, PDF 저장)
  → 견적 목록에서 "발송 처리" (sentAt 기록)
  → 7일 후 알람 카드 "견적 검토 확인" / 14일+ 미결 시 팔로업 카드
  → 결론 입력(견적 현황 or 드로어) → "계약 체결" = 수주
```

### B. 계약 전환 → 시험 일정
```
견적 드로어/고객 상세 "계약으로 전환"
  → Deal(안건) + Contract + Study 자동 생성
     · 효력: 설계된 시험기간 1건  · 독성: 라인별 임계경로 배치(조제물→단회→DRF→반복 등)
  → /gantt 에 기간 비례 막대  → /deals/[id] 에서 지급조건·마일스톤 관리
```

### C. CRM 계층과 드로어 내비
```
Company(고객사) → Contact(의뢰자) → Deal(안건) → {Quote, Contract, Study, Note, Event}
어느 화면에서든: 회사명 클릭 → 회사 드로어 → 그 안의 견적 클릭 → 견적 드로어(스택 뒤로가기)
견적 드로어 → "이 회사" / "견적서" / "수정"(위저드 재진입 ?id=) / "계약으로 전환"
```

### D. 데이터 유입
```
엑셀 업로드 3종(견적 현황·일일업무보고·잠재고객) → 미리보기(신규/갱신/오류) → 반영
잠재고객(Prospect) → 전환 → 고객사
```

## 6. 검토 요청 포인트 (알려진 약점 — 여기에 제안 집중)

1. **모바일 고밀도 화면**: 견적 목록(가로 스크롤 표), 카탈로그, 고객 상세 7탭, 간트. 폰에서의 대안 레이아웃(카드화? 우선 컬럼?) 제안 희망.
2. **위저드 모바일 UX**: 독성 위저드의 라이브 견적 패널이 폰에서 본문 아래로 밀려 금액을 보며 편집 불가. 효력 엔드포인트 매트릭스(26px 토글 셀)·노드 타임라인의 터치 UX.
3. **터치 타깃**: 수량 ±(28px)·행 액션(26px) 등 44px 미만 다수 — 단, 데스크톱 밀도는 유지해야 함.
4. **금액 표기 불일치**: 화면마다 ₩1.5억 / ₩150M / ₩150,000,000 혼용. 화면 맥락별 의도는 있으나 일관 규칙 제안 환영.
5. **홈 정보 위계**: 팔로업·알람·진행견적·마감시험·활동 카드가 늘며 스크롤이 길어짐 — 우선순위 재구성 여지.
6. **고객 상세 7탭**: 탭 나열보다 나은 정보 구조가 있는지.
7. **빈 상태·로딩 상태**: 현재 대부분 한 줄 텍스트 — 시스템화된 empty/loading 패턴 부재.
8. **위저드 구조 자체**: 현행은 선형 스테퍼(독성 5단계·효력 4단계). 더 나은 모델이 있으면 제안 환영 — 예: 단일 캔버스+사이드 요약, 좌측 폼/우측 문서 미리보기 분할, 섹션 아코디언, 대화형 진행 등. 특히 "입력하면서 금액 변화를 항상 본다"는 경험을 어떤 구조가 가장 잘 살리는지.
9. **간트 구조 자체**: 현행은 좌 목록 + 우 월단위 수평 막대. 대안 환영 — 타임라인 뷰, 스윔레인(고객사/담당자별), 밀도 전환(주/월/분기), 모바일 전용 세로 타임라인 등. 임계경로(선행→후행 의존)를 시각적으로 드러내는 아이디어면 더 좋음.

## 7. 절대 제약

### 7-A. 기능 계약 — 구조를 바꿔도 이 능력은 보존할 것

**독성 위저드** (`/quote-v2`)
- 수집 데이터: 프로젝트/고객 정보 → 모달리티(분류 2단) → 임상 계획(기간·경로·종·애드온·TK) → 항목·부형제 조정(수량·삭제·조건 토글) → 통화·할인. 순서는 재구성 가능하되 전부 수집돼야 함.
- 입력 변경 즉시 규칙엔진 재계산 → 금액·경고(missing_info)·자동 선행항목이 실시간 반영. 사용자는 편집 중 항상 현재 견적 금액을 볼 수 있어야 함.

**효력 위저드** (`/quote-efficacy`)
- 110개 질환모델 프리셋 선택(검색·카테고리 필터) → 선택 시 스케줄·군구성·엔드포인트 자동 구성.
- 편집 가능 요소: 스케줄 단계(유형·기간, 순서 있는 시퀀스), 군(하위분할 마리수), 엔드포인트×측정시점 매트릭스(시점 수가 가격에 반영됨), 동물(업체→종→주령 연동 셀렉트), 마진/할인.
- 역시 모든 편집이 실시간 재계산. 타임라인·매트릭스의 **시각화 방식은 완전 자유**(현행 노드 타임라인은 참고일 뿐).

**간트** (`/gantt`)
- 데이터: 프로젝트(안건)별 시험 목록, 각 시험의 시작·종료일(임계경로 배치됨), 4상태(예정/본시험/분석·평가/완료).
- 보존할 능력: 여러 시험의 기간 겹침 비교, 프로젝트 간 전환, 오늘 기준선.

**A4 견적서** (`/quote/print`) — 유일한 규격 고정: 210mm 페이지·분할·레터헤드·결재란. 내부 레이아웃 개선 제안은 가능하나 인쇄 규격 자체는 불변.

### 7-B. 공통
- 디자인 토큰(§2)·상태 어휘 변경 금지. 새 색상·새 폰트 도입 금지.
- 외부 서비스 연동 UI(소셜·알림톡 등) 추가 금지 — 폐쇄형 내부 도구.
- 다크모드는 토큰 스왑으로 동작해야 함(하드코딩 색 금지).
